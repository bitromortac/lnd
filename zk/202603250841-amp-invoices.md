# Atomic Multi-Path Invoices Dynamic Fulfillment

Atomic Multi-Path (AMP) invoices provide a mechanism for fulfilling a single
payment request through multiple distinct, uncoordinated payments. Unlike a
standard invoice, which creates a single payment hash that must be satisfied in
full, an AMP invoice generates a unique identifier called a Set ID for each
repeated payment instance.

This model enables a payer to break a large payment into smaller chunks—known as
"sub-invoices"—that traverse different channels and routes simultaneously. The
[invoice registry](202603250838-invoice-registry.md) tracks the state of each
sub-invoice separately, associating them with the overarching Set ID. When all
chunks arrive, the [invoice settlement flow](202603250837-invoice-settlement-flow.md)
can atomically verify and settle the entire set together.

The defining feature of AMP invoices is that the receiver does not know the
preimage required to settle the payments until all individual chunks have been
received. This cryptography ensures that either the entire desired amount is
received and settled, or none of it is, preserving the atomic nature of the
transaction across a decentralized network.
